# SK Translines ERP – modernised prototype

React 18 + TypeScript + Vite + Tailwind, rebuilt from the legacy SK Logistics ASP.NET source (234 ASPX pages, 115 EDMX entities).

## Run
    npm install
    npm run dev        # http://localhost:5173
    npm run build      # production build in dist/

## Structure
- `src/store/masters.ts` – master data seeded from the legacy LGST_* schema
- `src/store/seed.ts` – deterministic transactions (orders, LRs, rakes, GRN/DGRN, LDCs, bills, payments, trips, workshop)
- `src/store/store.ts` – Zustand store (persisted to localStorage) + every workflow action (`A.*`)
- `src/nav.ts` – information architecture, legacy-page mapping and role → module access
- `src/components/` – AppShell, DataTable, Drawer/Modal/Toasts/CommandPalette, charts, RecordDrawer (360 views), Print (A4 documents)
- `src/features/` – one file per domain: ops-orders, ops-lr, ops-rail, ops-delivery, fleet, warehouse, finance, workshop, customers, reports, masters, admin

Administration → Developer reference lists every legacy ASPX page and the screen that replaces it.


## Legacy data (SK Logistics backup)
The prototype boots on SK Logistics data converted from `ERPdatabase20250608.bak` (FY 2024-25 to 8 Jun 2025; ledger from 1 Mar 2025).
"Today" inside the app is 7 Jun 2025, the last working day in the backup. Switch to generated sample data, or restore the original data,
from Administration → System Settings → Data source. Working copies are kept in the browser's IndexedDB per data source.

- `src/store/legacy-data.ts` – the converted dataset (gzip + base64), generated by `scripts/embed-legacy.mjs`
- `src/store/dataset.ts` – loader (DecompressionStream), IndexedDB persistence, data-source preference
- Bump `LEGACY_VERSION` in `dataset.ts` whenever the embedded dataset changes so browsers reload it.
- The conversion toolkit (Python) that reads the .bak and produces this dataset is shipped separately.
